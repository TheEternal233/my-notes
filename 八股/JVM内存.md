## JVM 内存 = 一间出租屋

JVM 运行程序，就像租了一间房，里面分几个区域放东西。

------

## 五大区域（重点记前三个）



| 区域                      | 大白话           | 放什么                         |
| ------------------------- | ---------------- | ------------------------------ |
| **堆（Heap）**            | 大仓库，大家共用 | `new` 出来的对象，数组         |
| **栈（Stack）**           | 每个人的小抽屉   | 局部变量、方法参数，线程私有的 |
| **方法区（Method Area）** | 贴墙上的说明书   | 类信息、常量、静态变量         |
| 程序计数器                | 书签             | 线程执行到第几行代码了         |
| 本地方法栈                | 调用外援的桌子   | JNI 调用 C/C++ 方法时用        |

------

## 堆和栈的区别（最常考）



```
void method() {
    int a = 1;           // 栈里，方法结束就消失
    Person p = new Person();  // p 在栈里，Person 对象在堆里
}
```

表格

|          | 堆                               | 栈               |
| -------- | -------------------------------- | ---------------- |
| 存什么   | 对象实体                         | 变量名、基本数据 |
| 谁用     | 所有线程共享                     | 每个线程自己一份 |
| 生命周期 | 对象没人用了，垃圾回收（GC）才清 | 方法结束，自动清 |
| 大小     | 大，几百MB~几GB                  | 小，通常1MB左右  |

------

## 垃圾回收（GC）—— 堆里的保洁

堆里对象太多，JVM 会自动找"没人用的垃圾"清理掉。

**怎么判断垃圾？**

- **引用计数**：有人指着它就不是垃圾（但循环引用会漏，Java 不用这个）
- **可达性分析**：从"根"（栈里的变量、静态变量等）出发，能走到的就活着，走不到的就是垃圾

**回收算法**：

表格

| 算法      | 大白话                                   |
| --------- | ---------------------------------------- |
| 标记-清除 | 先标记垃圾，再扫掉，但会留下碎片         |
| 复制      | 把活着的复制到新地方，旧的整片清空       |
| 标记-整理 | 标记垃圾，清完后把活着的挤到一块，没碎片 |

------

## 一句话总结

> **堆放对象（共享，GC管），栈放变量（私有，自动清），方法区放类信息**

JVM 内存管理就是：东西该放哪放哪，垃圾定期扫，满了就 GC。
