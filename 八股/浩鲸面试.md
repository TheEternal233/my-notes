## ArrayList、LinkedList

ArrayList和LinkedList都是java中的常见集合类，都实现了List接口

> 底层数据结构不同：ArrayList使用动态数组实现，通过索引可快速定位元素；linkedList使用双向链表实现，每个节点存储元素本身和指向前与后的两个指针

> 插入和删除效率不同

> 随机访问效率不同:ArrayList通过索引快速访问元素

> 空间占用：ArrayList创建时会分配一段连续的空间，虽然会有一定的容量浪费，但只需要存储元素本身。LinkedList每个节点除了存储元素，还需要额外存储两个指针。所以在存储相同数量的元素下，LinkedList空间占用会大一些

> 使用场景：ArrayList 更适合需要频繁随机访问元素，或者主要在尾部进行插入、删除操作的场景。LinkedList 更适合需要频繁在头部或尾部进行插入、删除操作，或者需要作为双端队列、栈使用的场景；如果是通过迭代器直接操作已知位置的节点，在中间插入、删除时也能发挥它调整指针快的优势。

> 两个集合都是线程不安全的，多线程环境下需要自己加锁保证安全，或者使用线程安全的List集合，比如Collections.synchronizedList()包装的List或者CopyOnWriteArrayList

## Error、Exception

Java的异常体系主要基于Throwable及其子类，Throwable有两个重要子类：Error和Exception，它们分别代表了不同类型的异常情况

Error

> 错误，表示运行环境错误，错误是程序无法处理的严重问题，如虚拟机错误，动态链接库失效等。程序不应该尝试捕获这些错误，例如OutOfMemoryError，StackOverflowError等

Exception表示程序本身可以处理的异常情况

> 非运行时异常（受检异常）：这类异常在编译时就必须捕获或者声明抛出，通常是外部错误，比如文件不存在，类未找到等。非运行时异常强制程序员处理这些可能出现的问题，增强了程序的安全性
>
> 运行时异常（非受检异常）：这类异常特质RuntimeException及其子类，与Error一起构成了Java中非受检异常家族。主要由程序逻辑错误导致，如空指针访问，数组越界等，这类异常是不需要在编译时强制捕获或声明的

## 线程的状态

Java线程共有六种状态：

> NEW（新建）：线程对象已创建但尚未调用start方法
>
> RUNNABLE（可运行）：调用start后线程进入此状态，包含操作系统层面的“就绪”和“运行中”两种情形，Java层面将两者合并为RUNNABLE
>
> BLOCKED（阻塞）：线程等待进入synchronized同步代码块/方法时，因锁被其他线程持有而被阻塞
>
> WAITING（无期限等待）：调用Object.wait，Thread.join或LockSupport.park后进入，需要被其他线程显式唤醒
>
> TIMED_WAITING（期限等待）：调用带超时参数的sleep(long),wait(long),join(long),`LockSupport.parkNanos/parkUntil` 后进入，超时后会自动唤醒
>
> TERMINATED（终止）：线程的`run()` 方法执行完毕或因异常退出。

## Synchronized和ReentrantLock

二者都是Java中提供的可重入锁

> - **用法不同**：synchronized 可用来修饰普通方法、静态方法和代码块，而 ReentrantLock 只能用在代码块上。
> - **获取锁和释放锁方式不同**：synchronized 会自动加锁和释放锁，当进入 synchronized 修饰的代码块之后会自动加锁，当离开 synchronized 的代码段之后会自动释放锁。而 ReentrantLock 需要手动加锁和释放锁
> - **锁类型不同**：synchronized 属于非公平锁，而 ReentrantLock 既可以是公平锁也可以是非公平锁。
> - **响应中断不同**：ReentrantLock 可以响应中断，解决死锁的问题，而 synchronized 不能响应中断。
> - **底层实现不同**：synchronized 是 JVM 层面通过监视器实现的，而 ReentrantLock 是基于 AQS 实现的。

## CAS

CAS 就是"抢座位"

想象一群人抢一个座位（变量 `i = 0`）：

> - **普通做法（加锁）**：派个保安守着，一次只能一个人坐，其他人排队等着。慢，但安全。
> - **CAS做法（无锁）**：没有保安，每个人先**看一眼座位是不是空的**（预期值 A = 0），如果是，**赶紧坐上去**（改成 B = 1）。但如果同时有两个人看，都发现是空的，只有**第一个动手**的能坐上，第二个发现"咦，已经被占了"，就**重新看、重新抢**。

**代码对比**

~~~java
// 普通写法（线程不安全，会算错）
int i = 0;
i++;  // 两个线程同时读，都读到0，都+1，结果还是1，丢了1次

// CAS写法（AtomicInteger，线程安全）
AtomicInteger i = new AtomicInteger(0);
i.incrementAndGet();  // 内部就是CAS：先看是不是0，是就改成1，不是就重试
~~~

> **CAS = 我先看看值变没变，没变我就改，变了我就重新来**

不用锁，靠"看-改"的原子操作保证安全，但改失败了要**循环重试**（自旋），所以CPU会忙一会儿。

| 缺点         | 解释                                                         |
| :----------- | :----------------------------------------------------------- |
| **ABA**      | 值从0→1→0，你以为是原来的0，其实被人动过了。解决：加个版本号计数 |
| **自旋费电** | 一直抢一直抢，CPU在空转。解决：抢几次抢不到就老实去排队（锁） |

## AQS

AQS 就是"排队叫号机"

想象去银行办业务：

> - **窗口** = 锁（只有一个，谁拿到谁办事）
> - **叫号机** = AQS
> - **你** = 线程

**没有 AQS**：大家一窝蜂挤窗口，乱套。

**有 AQS**：取号排队，叫到你了再去，没叫到就坐着等。

| 功能              | 大白话                                             |
| :---------------- | :------------------------------------------------- |
| **状态（state）** | 窗口有没有人？0=空，1= occupied                    |
| **队列**          | 没抢到号的人坐哪等                                 |
| **抢号（CAS）**   | 谁先抢到号谁办事，用 CAS 保证不抢重                |
| **阻塞/唤醒**     | 没号的人去坐着（线程阻塞），办完了叫下一个（唤醒） |

代码

~~~java
// ReentrantLock 内部就是 AQS
Lock lock = new ReentrantLock();
lock.lock();   // 抢号，没抢到就排队等着
// ...办事...
lock.unlock(); // 办完了，叫下一个
~~~

> `ReentrantLock`、`Semaphore`、`CountDownLatch` 这些东西，**底层都是 AQS 在管排队**。

> **AQS = 一个专门管"谁拿锁、谁排队、怎么唤醒"的排队系统**

> CAS 负责抢，AQS 负责排，俩配合实现各种锁。
