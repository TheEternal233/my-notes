## 内存泄露 = 占着茅坑不拉屎

该扔的垃圾没扔，堆越堆越满，最后OOM（内存溢出）崩掉。

------

## 为什么会发生

**正常情况**：

```java
void method() {
    Person p = new Person();  // 堆里创建对象
} // 方法结束，p 从栈里消失，堆里的 Person 没人指向它 → GC 回收
```

**泄露情况**：

```java
List<Person> list = new ArrayList<>();  // 静态的，一直活着

void method() {
    Person p = new Person();
    list.add(p);  // p 被 list 抓住了
} // 方法结束，p 从栈消失，但 list 还指着它 → GC 不敢收
```

**结果**：每次调用都塞一个对象进 list，永远不被释放，堆越吃越胖，最后撑死。

------

## Java 常见泄露场景

| 场景                 | 大白话                                 | 例子                            |
| -------------------- | -------------------------------------- | ------------------------------- |
| **静态集合**         | 全局变量一直活着，里面的东西永远不被清 | `static List` 无限 add          |
| **未关闭资源**       | 开了门不关，占着位置                   | 数据库连接、文件流没 `close()`  |
| **监听器/回调**      | 注册了没注销，一直被调用者抓着         | 界面按钮监听，界面关了还在      |
| **ThreadLocal**      | 线程私有小仓库，线程池复用时旧数据没清 | 线程池 + ThreadLocal 组合       |
| **内部类持有外部类** | 内部类偷偷抓着外部类不放               | 匿名内部类引用 Activity（安卓） |

------

## 最典型例子：静态 Map

```java
public class Cache {
    private static Map<String, Object> map = new HashMap<>();  // 静态 = 永久存活
    
    public void put(String key, Object value) {
        map.put(key, value);  // 塞进去就永远在那，除非手动 remove
    }
}
// 越用越大，永远不释放 = 内存泄露
```

------

## 一句话总结

> **内存泄露 = 对象该死的时候还有人抓着它，GC 不敢收，堆越堆越满**

解决办法：用完及时 `remove`、`close`、`unregister`，别让不该活的东西赖着不走。
