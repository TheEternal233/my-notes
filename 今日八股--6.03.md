## Java里的集合怎么划分的

java集合框架主要分为两大类

| 接口       | 特点                   | 实现类             |
| ---------- | ---------------------- | ------------------ |
| Collection | 单列集合，存储单个元素 | List，Set，Queue   |
| Map        | 双列集合，存储键值对   | HashMap，TreeMap等 |

Collection子接口

> - List：无序，可重复（ArrayList，LinkedList，Vector）
> - Set：无序，不可重复（HashSet,LinkedHashSet,TreeSet）
> - Queue：队列，FIFO（LinkedList，PriorityQueue，ArrayDeque）

## 常用集合特点和区别

**List系列**

| 集合       | 底层结构   | 线程安全             | 特点                             |
| ---------- | ---------- | -------------------- | -------------------------------- |
| ArrayList  | Object数组 | 不安全               | 查询快O（1），增删慢             |
| LinkedList | 双向链表   | 不安全               | 增删快，查询慢O（n），内存占用大 |
| Vector     | Object数组 | 安全（synchronized） | 已过时，性能差                   |

**Set系列**

| 集合          | 底层结构                                | 特点                          |
| ------------- | --------------------------------------- | ----------------------------- |
| HashSet       | HashMap（key存元素，value为固定Object） | 无序，去重依赖hashCode+equals |
| LinkedHashSet | LinkedHashMap                           | 按插入顺序有序                |
| TreeSet       | 红黑树                                  | 自然排序或自定义比较器排序    |

**Map系列**

| 集合              | 底层结构           | 线程安全             | 特点                     |
| ----------------- | ------------------ | -------------------- | ------------------------ |
| HashMap           | 数组+链表+红黑树   | 不安全               | 无序，key、value可为null |
| LinkedHashMap     | 数组+链表+双向链表 | 不安全               | 按插入、访问顺序有序     |
| TreeMap           | 红黑树             | 不安全               | 按键排序                 |
| HashTable         | 数组+链表          | 安全（synchronized） | 过时，kv不为null         |
| ConcurrentHashMap | 数组+链表+红黑树   | 安全                 | 分段锁/CAS，高并发性能好 |

## JDK8对HashMap有什么优化

| 优化点         | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| 红黑树优化     | 链表长度>=8且数组长度>=64,链表转化为红黑树，查询从O（n）->O（log n） |
| 头插法改尾插法 | 扩容时改为尾插法，解决并发环境下的死循环问题（但仍不安全）   |
| 扩容优化       | 重新计算hash时，利用hash&oldCap判断位置，只需判断高位是0还是1，要么在原位置，要么在原位置+oldCap |
| hash计算简化   | hash=（h=key.hashCode（））^（h>>>16）,高位参与运算，减少冲突 |
| 扩容时机       | 插入后才检查扩容，jdk7是插入前                               |

## 创建长度为20的HashMap，，new时长度应该是多少

答案：32

HashMap构造函数传入的值会被调整为**大于等于该值最接近的2的幂**

## synchronized在什么场景下去用

> - 代码简单，竞争不激烈：synchronized语法简介，JVM优化后性能更好
> - 不需要高级功能：不需要可中断,超时，多条件唤醒等
> - 代码块较小：锁粒度可控
> - JVM内部机制：如StringBuffer，Vector（虽然已过时）

示例

~~~java
//简单计数器
public class Counter {
    private int count = 0;
    public synchronized void increment(){
        count++;
    }
    //或者更细粒度
    public void increment(){
        synchronized(this){
            count++;
        }
    }
}

~~~

## 单例模式怎么写

线程安全且高效的写法：DCL（双重检查锁定）

~~~java
public class Singleton {
    // volatile禁止指令重排序，保证可见性
    private static volatile Singleton instance;
    private Singleton(){}
    
    public static Singleton getInstance(){
        if(instance==null){		//第一次检查，无锁，提高性能
            synchronized (Singleton.class){	//同步块
                if(instance==null){			//第二次检查（防止多个线程重复创建）
                    instance=new Singleton();	//非原子操作：1.分配内存 2.初始化 3.负值
                    							//volatile保证2在3之前完成
                }
            }
        }
    }
}
~~~
